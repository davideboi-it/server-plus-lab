# Module 4.0 - Server Troubleshooting

## 1. Troubleshooting Methodology

A structured approach reduces guesswork, improves consistency, and minimizes downtime. 

### The 7-Step Troubleshooting Methodology
1. **Identify the Problem:** Gather information, identify symptoms, determine if anything changed.
2. **Establish a Theory of Probable Cause:** Question the obvious, establish a hypothesis.
3. **Test the Theory to Determine the Cause:** Once confirmed, determine the next steps. If the theory is incorrect, establish a new one or escalate.
4. **Establish a Plan of Action:** Plan how to resolve the problem and identify potential effects of your actions.
5. **Implement the Solution or Escalate as Necessary.**
6. **Verify Full System Functionality:** Implement preventive measures if applicable.
7. **Document Findings, Actions, and Outcomes:** Track symptoms, configs, and fixes to help with future incidents.

### Physical Safety First
* **Power down and unplug:** Always shut down and disconnect power before opening the chassis.
* **Avoid working alone:** Have someone nearby for emergencies (shock, heavy lifting).
* **Beware of hot components:** Let CPUs, heatsinks, and PSUs cool before touching.
* **Secure cables:** Avoid trip hazards.
* **Proper lifting:** Servers are heavy; lift with your legs and ask for help.
* **Sharp edges:** Wear gloves if necessary.
* **No conductive jewelry:** Remove rings and metal watches.
* **Check for residual power:** Wait a few minutes after disconnecting; capacitors hold charges.

### Immediate Information Gathering & Systematic Approach
* **Check the obvious:** Is it plugged in? Powered on? Cables connected? KVM working? Has this happened before?
* **Observe:** Look, listen, and smell (burning components?). Check POST codes/beeps and LED health indicators.
* **Identify recent changes:** Did it ever work? Was hardware swapped? Were patches applied?
* **Dig deeper:** Check logs (Event Viewer, `journalctl`, syslog, SIEM) and user reports.
* **Proceed systematically:** Change *one* variable at a time. If a change doesn't fix it, undo it before trying the next. Use known-good components to test.
* **Inspect for loose components:** Reseat RAM, expansion cards, drive backplanes, and cables.
* **Verify environment:** Check airflow, dust, power stability, and temp/humidity.

## 2. Resolving Common Server Failures

### Hardware-Related Troubleshooting
| Problem | Symptoms | Likely Causes | Investigation & Resolution |
| :--- | :--- | :--- | :--- |
| **Failure to Boot / POST Errors** | No display, beep codes, black screen. | Power failure, bad RAM, failed motherboard, misconfigured BIOS. | **Investigate:** PSU, cables, beeps, LEDs.<br>**Resolve:** Reseat components, replace parts, reset BIOS/CMOS. *(Note: If time resets, replace CMOS battery).* |
| **Overheating / Sudden Shutdown** | Unexpected power-off, thermal warnings, loud fans. | Dust, fan failure, degraded thermal paste. | **Investigate:** BIOS/IPMI temps, airflow.<br>**Resolve:** Clean with compressed air, replace fans, reapply thermal paste. |
| **Unresponsive Devices (GPU, RAID, HBA)**| Hardware not detected, errors in Device Manager or `dmesg`. | Driver issues, hardware fail, PCIe slot failure. | **Investigate:** Device Manager, BIOS.<br>**Resolve:** Reseat card, update firmware/drivers, move to a different slot. |

### Operating System & Software Troubleshooting
| Problem | Symptoms | Likely Causes | Investigation & Resolution |
| :--- | :--- | :--- | :--- |
| **Blue Screen / Kernel Panic** | Sudden crash, memory dump, system restart. | Driver conflict, hardware fault, bad RAM. | **Investigate:** Analyze dump file, logs, test RAM.<br>**Resolve:** Roll back updates, update drivers, replace RAM. |
| **System Lockups / Random Crashes** | Frozen screen, unresponsive keyboard/mouse. | Resource exhaustion, malware, overheating. | **Investigate:** Resource monitor, event viewer, malware scan.<br>**Resolve:** Kill runaway processes, patch software, remove malware. |
| **Service Failures** | Service not starting, refused connections (e.g., 500 Server Error). | Misconfiguration, port conflict, dependency failure. | **Investigate:** Logs, `systemctl` / `services.msc`, `netstat`.<br>**Resolve:** Reconfigure service, free up the port, restart dependencies. |

### Storage-Related Troubleshooting
| Problem | Symptoms | Likely Causes | Investigation & Resolution |
| :--- | :--- | :--- | :--- |
| **Boot Errors / OS Not Found** | "No boot device found", blinking cursor. | Disk failure, incorrect boot order, corrupted OS. | **Investigate:** BIOS boot order, disk status.<br>**Resolve:** Reinstall OS, fix bootloader, replace drive. |
| **Read/Write Errors / Data Corruption** | File access errors, slow writes, CRC errors, SMART warnings. | Failing disk, bad sectors, driver issues. | **Investigate:** SMART status, `chkdsk` / `fsck`, logs.<br>**Resolve:** Replace disk, restore from backup, run repair utilities. |
| **RAID / Logical Drive Errors** | Degraded array, missing volume, slow access. | Failed drive, rebuild in progress, mismatched disks. | **Investigate:** RAID controller logs, physical disk status.<br>**Resolve:** Replace failed disk, rebuild RAID, ensure matching drive specs. |

### Network-Related Troubleshooting
| Problem | Symptoms | Likely Causes | Investigation & Resolution |
| :--- | :--- | :--- | :--- |
| **No Connectivity / IP Conflicts** | "Unidentified network", can't ping gateway, no DNS, link light is on but no data. | DHCP failure, IP conflict, cabling, wrong VLAN. | **Investigate:** `ipconfig` / `ifconfig`, ARP tables, VLAN tags.<br>**Resolve:** Reassign IPs, fix DHCP/DNS, swap cable, correct VLAN.<br>*(Note: If some protocols work but not others, suspect a firewall rule).* |
| **Intermittent Drops** | Timeouts, dropped RDP/SSH sessions. | NIC driver issue, power saving mode, bottlenecks. | **Investigate:** Logs, NIC diagnostics, throughput.<br>**Resolve:** Update drivers, disable NIC power saving, reroute traffic. |
| **Slow/Poor Performance** | Long transfers, lag, audio/video jitter. | Duplex mismatch, bandwidth saturation, MTU mismatch. | **Investigate:** Switch port config, traffic analysis, `iperf`.<br>**Resolve:** Match duplex settings, adjust MTU, implement QoS. |
